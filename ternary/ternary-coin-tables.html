Ternary Coin Tables

Any whole number can be written with only −1, 0 and +1, if you have coins of different sizes: 1, 3, 9, 27. For each coin you either give it (+1), skip it (0), or take it back as change (−1).

Your 3 × 3 example

A small data matrix, like the output of a layer. Click any cell of the data to follow it through the tables.

1. Split the data into three coin tables

Each number is written with the 9, 3 and 1 coins. Collect all the nines digits into one table, the threes into another, the ones into a third. Every table holds only −1, 0, +1.

2. Multiply each table by the ternary weights ternary × ternary

Both sides are −1, 0, +1, so every product is −1, 0 or +1 and every multiply is just adding and subtracting. You do this three times, once per table.

3. Combine with the coin values

Multiply the three results by 9, 3 and 1 and add them. That gives exactly the same answer as multiplying the original data by the weights.

Multiplying two ternary rows with bits

A dot product of two ternary rows (one row of Q with one row of K, say) can be done without any multiplying. Each row is stored as two rows of bits: one marks the +1s, the other marks the −1s. Zeros are off in both. Click any digit to change it.

1. Two ternary rows

2. Store each row as two rows of bits

A 1 means "this position is +1" (in the plus row) or "this position is −1" (in the minus row).

3. Four ANDs, four counts

AND keeps a 1 only where both bit rows have a 1. Counting the 1s (a popcount) tells how many positions match. Same signs add, opposite signs subtract.

4. The answer

why it is fast

64 digits per step

A computer word holds 64 bits, so one AND and one popcount handle 64 positions at once. A full dot product of 64 digits is 4 ANDs, 4 counts and 3 adds, with no multiplying.

stacked tables

Every table pair gets this treatment

With 3 coin tables on each side, Q · K needs 9 table pairs, each done with these 4 counts, then weighted by 81, 27, 27, 9, 9, 9, 3, 3 and 1 and added.

open question

Do GPUs win with this?

GPUs have far fewer bit-counting units than their fast 8-bit multiply units. Whether this beats plain 8-bit on a GPU has not been shown. It can be tested.

What it costs

exact

Nothing is lost

The tables represent every number exactly, as long as you have enough coin sizes for the biggest number.

cost

One multiply becomes several

Three tables means three ternary multiplies instead of one. Five tables covers the same range as 8-bit data, so it is five cheap multiplies against one 8-bit multiply.

repeat

The output is not ternary again

The combined result is ordinary whole numbers (see step 3). Before the next layer it has to be split into coin tables again.

unproven

Whether it saves anything

It pays off only on hardware where a ternary × ternary multiply is much cheaper than an 8-bit one. On a normal CPU that is untested and may not hold.

This number system is called balanced ternary. It is old: the Soviet Setun computer used it in 1958. Splitting numbers into layers like this is also known as bit-plane or bit-serial computing.
